# Goofish signing runtime

Goofish (闲鱼) MTOP requests must be signed by Alibaba's
SecurityGuard native library. ZeroSearch runs that library under
[unidbg](https://github.com/zhkl0228/unidbg) — a JVM Android
emulator — via a small harness (`local.goofish.SgHarness`, sources
vendored under `harness/`), and speaks to it over stdio in a
JSON-lines "serve" protocol.

From the server's point of view this is all automatic:

- the server auto-discovers a `goofish-runtime/` bundle next to the
  server executable (or in its data directory) and starts it on the
  first Goofish call;
- the device identity is generated by the server itself on first
  use — with the app's own UTDID algorithm — and persisted in the
  server's data directory. There is nothing to configure and no
  environment variable to set.

## Assembling the bundle

The bundle cannot be committed to this repository: it embeds the
Goofish Android APK (~269 MB, Alibaba-proprietary) and ~350 MB of
emulator state. `bootstrap.sh` assembles it from the vendored
harness sources, Maven Central dependencies, and an APK you supply:

```sh
./bootstrap.sh /path/to/idlefish_7.28.70.apk
# → target/release/goofish-runtime/ (next to the built server)
```

Requirements at assembly time only: JDK 8, Maven, Python 3.

Bundle layout:

```
goofish-runtime/
  serve.sh          # entry point the server spawns
  goofish.apk       # the supplied APK (validated + staged by the harness)
  harness/          # compiled SgHarness classes (patched/ + target/)
  m2repo/           # unidbg 0.9.9 and transitive jars
  libs/             # SecurityGuard .so files extracted from the APK
  rootfs/           # emulator root filesystem (harness-managed)
```

The first Goofish call after startup takes a few minutes while the
harness boots and initialises SecurityGuard; later calls in the
same server process reuse the running harness.
